# 备份与恢复流程

备份对象必须独立于应用发布。应用发布可以替换容器，但不能删除 Volume、数据库、对象存储或队列。

## 分层

| 数据 | 首选存储 | 备份方式 | 恢复验证 |
|---|---|---|---|
| MySQL | RDS MySQL；迁移前保留本地副本 | 每日逻辑备份，必要时加增量/binlog | 在隔离实例导入并执行业务查询 |
| PostgreSQL | RDS PostgreSQL | `pg_dump` 或托管快照 | 新实例恢复、迁移、健康检查 |
| Redis | 托管 Redis | 先确认是缓存、Session 还是队列；按用途决定是否备份 | 验证登录、任务和锁行为 |
| RabbitMQ | 托管 RabbitMQ | 导出 definitions；消息由业务重放或排空 | 校验交换机、队列、消费者和未完成任务 |
| 上传文件/媒体 | OSS | 对象版本控制、独立 Bucket 备份 | 抽样下载并校验对象数量和哈希 |
| Meilisearch | 可重建索引 | 快照到 OSS；主数据仍以数据库为准 | 从数据库重新索引并完成搜索冒烟 |
| Traefik | 配置和证书服务 | `traefik.yml`、动态配置、ACME 文件加密备份 | 隔离环境启动并校验所有路由 |
| New API | 外部数据库或独立数据目录 | 数据库备份 + 配置备份 | 登录、Provider、额度和请求冒烟 |

默认保留策略：7 份日备份、4 份周备份、12 份月备份。备份必须加密，备份任务本身要有失败告警。服务器本地副本只作为上传缓存，不能作为唯一备份。

## 每次备份

1. 生成服务和数据版本清单。
2. 对数据库执行一致性备份。
3. 上传到独立 OSS Bucket，路径为 `service/environment/date/`。
4. 写入校验和、来源、时间、工具版本和恢复命令。
5. 抽样下载校验；失败时标记备份不可用。

## 恢复演练

1. 在隔离服务器或临时数据库创建空环境。
2. 恢复数据库和对象文件。
3. 恢复非敏感配置，并从密钥管理系统注入密钥。
4. 启动应用镜像，执行迁移和健康检查。
5. 验证登录、核心 API、异步任务、文件访问和搜索。
6. 记录恢复用时、缺失数据、人工步骤和新的修复项。

生产恢复必须单独使用受保护的 GitHub Environment，默认只允许 `restore-check`，不允许工作流直接覆盖生产数据。
